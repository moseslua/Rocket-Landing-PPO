# Full implementation contract (development baseline)

This expands the ideal point-mass foundation into an executable research pipeline. It does not freeze hypotheses, claim G1–G5, validate high-fidelity physics, or replace large seeded experiments.

## Required public behavior
1. Rigid-body state layout is exactly [r3, v3, scalar-first body-to-ENU quaternion4, body angular rate3, mass1]. Action is normalized throttle, pitch/yaw gimbal, and RCS roll. Torque-free rotation has independent analytic reference tests. JAX fixed RK4 and independent NumPy/SciPy reference agree with optional effects off.
2. Trainable environment has normalized observations with six attitude entries, prior action, optional baseline action, physics-rate observation delay/noise, bounded domain randomization, reward and three separate CMDP costs, explicit termination, timeout, bounds, landing criteria, absorbing terminal transitions, and optional auto-reset. Asymmetric critic data is noise-free and never supplied to the actor. Wind is a translational acceleration (explicitly not aerodynamic relative-flow drag).
3. Point-mass training adapter supports E0; full 6-DOF adapter supports all main experiments. Gymnasium adapter is outside JAX hot paths. `check_env` and deterministic resets are tested.
4. B0 uses a real CVXPY/Clarabel finite-horizon convex translational program and quaternion attitude tracking. It is a receding-horizon baseline, not a globally fuel-optimal/open-loop certified powered-descent solver. Residual actions are baseline plus bounded learned correction. Action composition is tested.
5. PPO uses clipped ratios, GAE, separate actor/reward and cost critics, minibatch epochs, gradient clipping, entropy/value coefficients, and optional running normalization. PID-Lagrangian has one nonnegative capped multiplier per constraint. Penalty and residual variants share numerical environments and RNG seeding. SAC has a bounded replay buffer, twin Q targets, tanh Gaussian policy, target soft updates, and learned temperature. Training accepts explicit total step budgets; no test claims convergence at 500M steps.
6. Training/tuning/evaluation commands are Hydra-driven. Experiment registrations E0–E5 exist and preserve methods/seeds as explicit config. Development smoke profiles are visibly distinct from frozen research profiles. Test-set generator writes hashed scenarios once; evaluator refuses modified sets and provides success/violation/fuel/touchdown/tail/smoothness/inference metrics. Frozen data is never sampled for tuning or used in smoke tests.
7. Every run records resolved config, seed, git commit and dirty status, source and lock hashes, simulator versions, dependencies, backend, and timestamps. Final checkpoints are safe msgpack parameters, not Python pickle. All runs, including negative results, are recorded. Figures are generated from run artifacts and have Make targets.
8. Tests cover physics, determinism, environment boundaries, rewards/costs, guidance feasibility/fallback, residual composition, policy gradient updates, replay/SAC updates, immutable evaluation, statistics, CLI configs, checkpoint round trips, and end-to-end CPU smoke training. Docker and CUDA are separate environment verification concerns.

## Scientific limits
The development vehicle and reward ranges remain configurable and unfrozen. Feasibility sampling uses a thrust-cap envelope check and optional convex solve, not proof that every attitude-disturbance trajectory is feasible. High-fidelity effects are independently implemented development models, not validated against external vehicle data. DOP853/RK45 selection and G4 parameter freezing remain open research decisions. 250 GPU-hours, 10-seed experiments, 500M steps, success-rate gates, and paper claims are not completed by this engineering work.
